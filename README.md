# FluxDown Plugin Index

**The plugin index for [FluxDown](https://fluxdown.com) — a content-addressed, Git-versioned catalog of plugins.**

Not a website — a **verifiable data format**. FluxDown discovers, downloads, and verifies plugins directly from this Git repository.

## English

### What this is

This repository **is** the marketplace: a Git-versioned, content-addressed index that any FluxDown client fetches, verifies, and installs from. There is no backend and no account. Authors keep their plugin in **their own GitHub repository**; registering it here once is enough — every later GitHub Release is picked up automatically. You can fork this repo to host your own index.

### Design principles

| Principle | How it is realized |
|---|---|
| **Authors own their repos** | `registry.json` binds one plugin identity to one GitHub repository. The author's Latest Release asset is the download source. |
| **Register once, update automatically** | The hourly Stage job ingests each new Latest Release: hash, unpack, validate, append a shard, republish `index.json`. No PR per version. |
| **Content-addressed** | `contentHash = sha256(entire .fxplug zip)` is the single source of truth. A client accepts a download from *any* mirror as long as the hash matches. |
| **Immutable versions** | Shards are append-only. A version's bytes never change; a swapped release asset is detected and reported, and clients reject it by hash. |
| **Rollback protection** | A global monotonic `sequence`. Clients persist a per-`indexId` high-water mark and reject any index whose sequence regresses. |
| **Consent matches the package** | Shard `permissions[]` are copied from the package manifest by Stage; the client also refuses packages whose manifest identity, version, or permissions differ from the index entry. |

> **Signing (v1 note).** Author-level signatures (sigstore / ed25519) are a planned enhancement; the schema reserves `sigScheme` / `sigstoreBundleRef`. The integrity base is **content addressing (sha256) + transport TLS + Git history**.

### Repository layout

```
registry.json                        Author registry: plugin identity ↔ GitHub repo (the only file authors edit)
STATE                                Index identity (indexId UUID) + sequence high-water mark
index.json                           Flattened full catalog — the client fetch entry point (generated)
plugins/<pluginId>/<version>.json    One shard per plugin per version (append-only, generated by Stage)
dist/<name>-<version>.fxplug         Legacy packages published before the registry (append-only)
scripts/package-lib.mjs              .fxplug reader + manifest admission (mirrors the client's install rules)
scripts/stage-lib.mjs / stage.mjs    Stage: Latest Release → shard → index.json; stage-fail issues
scripts/check-registry.mjs           Registry PR check (dry-run Stage, PR comment)
scripts/index-lib.mjs                Shared content/history admission rules
scripts/validate.mjs / generate.mjs  Offline admission / deterministic flatten
scripts/check-mirrors.mjs            Online full-GET/hash validation of every mirror
.github/workflows/                   stage.yml (hourly + on registry change), registry-check.yml, validate.yml
```

### Publishing a plugin

**Your repository**

1. Develop the plugin in your own public GitHub repository (`manifest.json` + scripts; see the [plugin docs](https://fluxdown.com/docs/en/plugins/packaging/)).
2. Publish a GitHub Release (not draft, not pre-release) with **exactly one** `.fxplug` asset. The manifest `version` must be strict `MAJOR.MINOR.PATCH` and higher than every version already in the index. Enabling GitHub [immutable releases](https://github.blog/changelog/2025-10-28-immutable-releases-are-now-generally-available) is recommended.

**Register once**

3. Open a PR that only adds your entry to `registry.json`:

   ```json
   { "id": "author@name", "repo": "owner/repo", "tags": ["resolver", "video"] }
   ```

   `id` must equal the manifest `identity`; one repository hosts one plugin; `tags` (optional, ≤10 lowercase) are shown in the market.
4. The **registry-check** bot downloads your Latest Release, runs the full admission and comments with the result, the declared permissions, and the URL patterns the plugin intercepts. Fix your release and push to the PR to re-run.
5. A maintainer reviews and merges. Stage publishes your plugin within minutes.

**Updates**

6. Just publish a new Release. Stage runs hourly; on success the new version appears in the market. On failure an issue labeled `stage-fail` is opened (and closed automatically once fixed) — no new PR needed.

### Admission rules (PR check and Stage)

| Check | Rule |
|---|---|
| Release | Latest Release of the registered repo, exactly one `.fxplug` asset on that repo's `releases/download` URL |
| Bytes | ≤ 10 MiB; sha256 equals GitHub's asset digest when present |
| Zip | ≤ 200 entries, ≤ 50 MiB unpacked, no `..`/absolute/backslash paths, no symlinks or encrypted entries, CRC verified; `manifest.json` at root or in one wrapper folder |
| Manifest | Same schema as the client (unknown keys, identity, settings widget×type matrix, events, permissions `ffmpeg`/`ytdlp`/`auth`/`tasks`/`browserRules`/`desktop`/`background`/`intercept`/`pageScripts`, `interceptors`/`main`/`contributes` rules, `auth`/`intercept`/`pageScripts`/`browserRules`/`desktop` blocks require their permission); every `entry`/`icon` file exists |
| Identity | Manifest `identity` equals the registered `id` |
| Version | Strictly greater than every published version; identical bytes only add the release as a mirror of the existing version |
| Immutability | A staged release asset whose digest changes is reported; the published version keeps its bytes |

Updates are fully automatic: first registration is reviewed by a maintainer, later releases are not. Permissions are always shown to users before installing.

### Generated shard fields

| Field | Source |
|---|---|
| `pluginId`, `version`, `name`, `description`, `minAppVersion`, `permissions[]` | Package manifest |
| `contentHash` | sha256 of the release asset |
| `sequence` | Next global sequence above `STATE`, `index.json` and every shard |
| `author` / `homepage` | Registered repository owner / URL |
| `mirrors[]` | The release asset URL |
| `publishTime` | Release `published_at` (also drives `index.json.updated`) |
| `tags[]` | `registry.json` |
| `yanked` | `none`; maintainers may set `deprecated` / `vulnerable` / `malicious` |
| `sigScheme` / `sigstoreBundleRef` | Reserved (`none`) |

### Maintainer operations

- **Yank**: edit the shard's `yanked` (`vulnerable` / `malicious` also disable installed copies on clients); regenerate with `node scripts/generate.mjs`.
- **Delist**: remove the entry from `registry.json` (Stage stops ingesting and closes its `stage-fail` issue); yank versions that must disappear from installs.
- **Maintainer change**: a PR re-pointing `repo` for an existing `id`; the bot flags it and the previous maintainer must confirm in the PR. The new version must still be higher.
- **Re-check a PR**: run the `registry-check` workflow manually with the PR number.

### The `.fxplug` package

A `.fxplug` is a plain zip of the plugin directory with `manifest.json` at the root (or inside a single wrapper folder). The runtime is a sandboxed QuickJS engine. Manifest keys:

| Manifest key | Purpose |
|---|---|
| `identity` / `name` / `version` | Identity `^[a-z0-9_-]+@[a-z0-9_-]+$`; three-part semver. |
| `description` / `homepage` / `icon` | Metadata; `icon` is a safe relative path inside the package. |
| `minAppVersion` | Minimum host version. |
| `resolvers[]` | At most one. `{ match: { urls: [...] }, entry, timeoutMs?, multi? }`; resolves a page to a direct link. |
| `subscriptions[]` | At most one provider `{ providerId, entry, timeoutMs? }` (`rss` is reserved). |
| `hooks` | `{ entry, events, match? }`; `events` ⊆ `onStart` / `onError` / `onDone` / `onMetaProbed` / `onCancel`. |
| `auth` | `{ entry, timeoutMs? }` platform login; requires the `auth` permission. |
| `settings[]` | Declarative settings rendered on desktop and web (`text` / `password` / `textarea` / `folder` / `select` → `string`; `toggle` → `boolean`; `number` → `number`). |
| `permissions[]` | `ffmpeg`, `ytdlp`, `auth`, `tasks`, `browserRules`, `desktop`, `background`, `intercept`, `pageScripts`. Unknown values reject the manifest — pair a new permission with a `minAppVersion` bump. |

Full API reference: <https://fluxdown.com/docs/en/plugins/api-reference/>.

### Validation commands

Node 20 or later, no dependencies:

```sh
node --test scripts/index.test.mjs scripts/stage.test.mjs
node scripts/validate.mjs
node scripts/validate.mjs --base /path/to/exact-base-checkout
node scripts/check-mirrors.mjs
GITHUB_TOKEN=… node scripts/stage.mjs --root /tmp/index-copy        # dry-run Stage on a copy
GITHUB_TOKEN=… node scripts/check-registry.mjs --head registry.json # PR check locally
```

The first three are offline. `--base` takes a complete checkout of the exact published base commit (CI uses `pull_request.base.sha` / `push.before`; Stage pins the pre-stage `HEAD`). Missing baselines and shallow history fail admission. Published shards, legacy `dist/` packages, identities, versions, hashes and sequences cannot be deleted or rewritten; mirror and display metadata repairs are allowed. `check-mirrors.mjs` GETs every mirror in full (45 s, 10 MiB, ≤5 HTTPS/public-host redirects).

### How the client consumes it

FluxDown's `plugin::market::MarketClient`: fetch `index.json` (multi-source failover) → verify the sequence has not regressed → download the `.fxplug` from the first working mirror → pin-compare against `contentHash` → verify the manifest identity / version / permissions match the entry → install through the shared pipeline (zip-slip / zip-bomb protection + manifest validation).

## 简体中文

### 这是什么

本仓库**本身**就是市场：一份 Git 版本化、内容寻址的索引，FluxDown 客户端从这里发现、校验并安装插件。无后端、无账号。作者把插件放在**自己的 GitHub 仓库**里维护，在这里登记一次即可——之后每次 GitHub Release 都会被自动收录。你也可以 fork 本仓库自建索引。

### 设计要点

| 原则 | 实现方式 |
|---|---|
| **作者维护自己的仓库** | `registry.json` 把一个插件 identity 绑定到一个 GitHub 仓库；作者 Latest Release 的附件就是下载源。 |
| **登记一次，自动更新** | 每小时运行的 Stage 收录每个新的 Latest Release：算哈希、解包、校验、追加分片、重新发布 `index.json`。不必每个版本提 PR。 |
| **内容寻址** | `contentHash = sha256(整个 .fxplug zip)` 是唯一真相源；从任一镜像取回，哈希吻合即接受。 |
| **版本不可变** | 分片只增不删；同一版本字节永不改变。Release 附件被替换会被发现并上报，客户端按哈希拒绝。 |
| **防回滚** | 全局 `sequence` 单调递增；客户端持久化 per-`indexId` 高水位，索引回退即拒绝。 |
| **授权与包一致** | 分片 `permissions[]` 由 Stage 从包内 manifest 抄录；客户端还会拒绝 manifest 的 identity / 版本 / 权限与索引条目不一致的包。 |

> **v1 签名说明。** 作者级签名（sigstore / ed25519）为后续增强，schema 已预留 `sigScheme` / `sigstoreBundleRef`。当前完整性基座 = **内容寻址（sha256）+ 传输层 TLS + Git 历史**。

### 目录结构

```
registry.json                        作者登记表：插件 identity ↔ GitHub 仓库（作者唯一需要编辑的文件）
STATE                                索引身份（indexId UUID）+ sequence 高水位
index.json                           flatten 后的全量目录 —— 客户端拉取入口（生成）
plugins/<pluginId>/<version>.json    每插件每版本一份分片（只增不删，由 Stage 生成）
dist/<name>-<version>.fxplug         登记表出现前发布的历史包（只增不删）
scripts/package-lib.mjs              .fxplug 读取 + manifest 准入（与客户端安装规则对齐）
scripts/stage-lib.mjs / stage.mjs    Stage：Latest Release → 分片 → index.json；stage-fail issue
scripts/check-registry.mjs           登记 PR 检查（Stage 演练 + PR 评论）
scripts/index-lib.mjs                共享内容 / 历史准入规则
scripts/validate.mjs / generate.mjs  离线准入 / 确定性 flatten
scripts/check-mirrors.mjs            对每个镜像完整 GET 并核验哈希
.github/workflows/                   stage.yml（每小时 + 登记变更）、registry-check.yml、validate.yml
```

### 发布一个插件

**你的仓库**

1. 在自己的公开 GitHub 仓库开发插件（`manifest.json` + 脚本，见[插件文档](https://fluxdown.com/docs/zh/plugins/packaging/)）。
2. 发布 GitHub Release（非草稿、非预发布），附件中**恰好一个** `.fxplug`。manifest `version` 须为严格的 `MAJOR.MINOR.PATCH`，且高于索引中已有的所有版本。建议开启 GitHub [不可变 Release](https://github.blog/changelog/2025-10-28-immutable-releases-are-now-generally-available)。

**登记一次**

3. 提一个只修改 `registry.json` 的 PR，追加：

   ```json
   { "id": "author@name", "repo": "owner/repo", "tags": ["resolver", "video"] }
   ```

   `id` 必须等于 manifest `identity`；一个仓库只发布一个插件；`tags` 可选（≤10 个小写标签），用于市场展示。
4. **registry-check** 机器人会下载你的 Latest Release，跑完整准入，并在 PR 里评论结果、声明的权限和插件拦截的 URL 规则。修好 Release 后向 PR 推送任意提交即可重跑。
5. 维护者审核合并，Stage 在几分钟内收录。

**更新**

6. 直接发布新 Release。Stage 每小时运行一次，成功后新版本出现在市场；失败时开一个 `stage-fail` 标签的 issue（修复后自动关闭），无需再提 PR。

### 准入规则（PR 检查与 Stage 共用）

| 检查 | 规则 |
|---|---|
| Release | 登记仓库的 Latest Release，恰好一个 `.fxplug` 附件，地址属于该仓库的 `releases/download` |
| 字节 | ≤ 10 MiB；GitHub 提供附件 digest 时 sha256 必须一致 |
| Zip | ≤ 200 个条目、解压 ≤ 50 MiB；禁 `..` / 绝对路径 / 反斜杠、符号链接、加密条目；校验 CRC；`manifest.json` 在根目录或唯一包裹目录内 |
| Manifest | 与客户端同一 schema（未知字段、identity、设置 widget×type 矩阵、事件、权限 `ffmpeg` / `ytdlp` / `auth` / `tasks` / `browserRules` / `desktop` / `background` / `intercept` / `pageScripts`，`interceptors` / `main` / `contributes` 规则，`auth` / `intercept` / `pageScripts` / `browserRules` / `desktop` 声明须带对应权限）；所有 `entry` / `icon` / `main` / 页面脚本 / 嗅探规则文件必须存在 |
| 身份 | manifest `identity` 等于登记的 `id` |
| 版本 | 严格高于全部已发布版本；字节完全相同则只把 Release 追加为该版本的镜像 |
| 不可变 | 已收录的 Release 附件 digest 变化会被上报，已发布版本字节不变 |

更新全自动：首次登记由维护者人工审核，之后的版本不再人工审核；安装前客户端始终向用户展示权限。

### 生成的分片字段

| 字段 | 来源 |
|---|---|
| `pluginId`、`version`、`name`、`description`、`minAppVersion`、`permissions[]` | 包内 manifest |
| `contentHash` | Release 附件 sha256 |
| `sequence` | 高于 `STATE`、`index.json` 与所有分片的下一个全局序号 |
| `author` / `homepage` | 登记仓库的 owner / 地址 |
| `mirrors[]` | Release 附件地址 |
| `publishTime` | Release `published_at`（同时决定 `index.json.updated`） |
| `tags[]` | `registry.json` |
| `yanked` | `none`；维护者可改为 `deprecated` / `vulnerable` / `malicious` |
| `sigScheme` / `sigstoreBundleRef` | 预留（`none`） |

### 维护者操作

- **撤回**：修改分片 `yanked`（`vulnerable` / `malicious` 会让客户端停用已安装副本），再跑 `node scripts/generate.mjs`。
- **下架**：从 `registry.json` 删除条目（Stage 停止收录并关闭其 `stage-fail` issue）；需要从用户端消失的版本另行撤回。
- **更换维护者**：PR 把已有 `id` 的 `repo` 指向新仓库；机器人会标注，须原维护者在 PR 中确认，新版本号仍须更高。
- **重跑 PR 检查**：手动运行 `registry-check` workflow 并填 PR 号。

### `.fxplug` 插件包

`.fxplug` 是插件目录的普通 zip，`manifest.json` 位于根目录（或唯一一层包裹目录内）。运行时是沙箱化 QuickJS。manifest 字段：

| Manifest 字段 | 用途 |
|---|---|
| `identity` / `name` / `version` | 标识 `^[a-z0-9_-]+@[a-z0-9_-]+$`；三段 semver。 |
| `description` / `homepage` / `icon` | 元数据；`icon` 为包内安全相对路径。 |
| `minAppVersion` | 最低宿主版本。 |
| `resolvers[]` | 至多一个。`{ match: { urls: [...] }, entry, timeoutMs?, multi? }`，把页面解析为直链。 |
| `subscriptions[]` | 至多一个 provider `{ providerId, entry, timeoutMs? }`（`rss` 为保留字）。 |
| `hooks` | `{ entry, events, match? }`；`events` ⊆ `onStart` / `onError` / `onDone` / `onMetaProbed` / `onCancel`。 |
| `auth` | `{ entry, timeoutMs? }` 平台登录入口；须声明 `auth` 权限。 |
| `settings[]` | 声明式设置，桌面与 Web 自动渲染（`text` / `password` / `textarea` / `folder` / `select` → `string`；`toggle` → `boolean`；`number` → `number`）。 |
| `permissions[]` | `ffmpeg`、`ytdlp`、`auth`、`tasks`、`browserRules`、`desktop`、`background`、`intercept`、`pageScripts`。未知值拒绝整份 manifest —— 新增权限时一并抬高 `minAppVersion`。 |

完整 API 参考：<https://fluxdown.com/docs/zh/plugins/api-reference/>。

### 校验命令

要求 Node 20+，无依赖：

```sh
node --test scripts/index.test.mjs scripts/stage.test.mjs
node scripts/validate.mjs
node scripts/validate.mjs --base /path/to/exact-base-checkout
node scripts/check-mirrors.mjs
GITHUB_TOKEN=… node scripts/stage.mjs --root /tmp/index-copy        # 在副本上演练 Stage
GITHUB_TOKEN=… node scripts/check-registry.mjs --head registry.json # 本地跑 PR 检查
```

前三条离线执行。`--base` 为已发布精确 commit 的完整 checkout（CI 用 `pull_request.base.sha` / `push.before`；Stage 固定为收录前的 `HEAD`）。缺失基线或 shallow 历史直接失败。已发布分片、历史 `dist/` 包、identity、版本、哈希与 sequence 不得删除或改写；允许修复镜像与展示元数据。`check-mirrors.mjs` 对每个镜像完整 GET（45 秒、10 MiB、≤5 次 HTTPS / 公网重定向）。

### 客户端如何使用

FluxDown 引擎的 `plugin::market::MarketClient`：拉 `index.json`（多源 failover）→ 校验 sequence 不回退 → 从首个可用镜像下载 `.fxplug` → 用 `contentHash` 钉住比对 → 核对 manifest 的 identity / 版本 / 权限与条目一致 → 复用安装管线（zip-slip / 压缩炸弹防护 + manifest 校验）安装。
